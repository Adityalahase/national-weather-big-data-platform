# Database Loading (PostgreSQL)

SIH 2026 – National Weather Big Data Analytics Platform (PS 26069)
Role: Data Engineer — Step 4.

## Purpose
Loads the latest cleaned weather CSV (from `../cleaning/data/processed/`) into the existing `weather_data` table in the `weather_platform` PostgreSQL database.

This script does **not** create or alter the database or table — both must already exist.

## PostgreSQL setup (already done)
- Database: `weather_platform`
- Table:
```sql
CREATE TABLE weather_data (
    id SERIAL PRIMARY KEY,
    timestamp TIMESTAMP NOT NULL,
    latitude DOUBLE PRECISION,
    longitude DOUBLE PRECISION,
    timezone VARCHAR(100),
    temperature_c DOUBLE PRECISION,
    relative_humidity_pct DOUBLE PRECISION,
    precipitation_mm DOUBLE PRECISION,
    wind_speed_kmh DOUBLE PRECISION,
    weather_code INTEGER
);
```

## Environment variables
The script reads credentials only from environment variables — never hardcoded.

| Variable | Example |
|---|---|
| `DB_HOST` | `localhost` |
| `DB_PORT` | `5432` |
| `DB_NAME` | `weather_platform` |
| `DB_USER` | `postgres` |
| `DB_PASSWORD` | *(your actual password)* |

Copy the template and fill in your real password:
```bash
cp .env.example .env
# then edit .env
```
`.env` is already covered by the root `.gitignore` (`.env` pattern), so it will never be committed. Only `.env.example` (with a placeholder password) is tracked in Git.

The script loads `.env` itself (no extra dependency) if present, or you can `export` the variables directly in your shell instead.

## Install dependencies
```bash
cd data-engineering/database
pip install -r requirements.txt
```

## Run the loader
```bash
cd data-engineering/database
python load_to_postgres.py
```
It automatically finds the most recently modified `weather_cleaned_*.csv` in `../cleaning/data/processed/` — no path needs to be passed manually.

Prerequisite: run `cleaning/clean_weather.py` at least once first so a cleaned CSV exists.

## Verify inserted records
Using `psql` or any PostgreSQL client connected to `weather_platform`:
```sql
SELECT * FROM weather_data;
SELECT COUNT(*) FROM weather_data;
```

## Behavior notes
- Uses a single parameterized `INSERT` statement (`%s` placeholders) — no string-built SQL.
- Missing/NaN values in the CSV are inserted as SQL `NULL`, never invented.
- On any insertion error, the transaction is rolled back and the connection is still closed safely.
- `id` is left out of the insert — it's auto-generated by the table's `SERIAL` column.
